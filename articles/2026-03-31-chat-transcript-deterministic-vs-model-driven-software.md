# 對話紀錄：從 deterministic 軟體到 model-driven 軟體

這篇文章整理一段關於軟體從 deterministic 走向 model-driven 的對話紀錄，保留使用者提問、概念釐清，以及後續將內容發到 GitHub Blog 的過程。

## 對話原文

### User

大部分的工程師還在用軟體寫 determistic 的程式時，一個流程給所有客戶用時

軟體世界已經悄悄的轉換到 non determistic ，大多數的軟體，將內建一個會根據你的使用環境跟使用經驗，建立一個機器學習的模型出來

解釋一下

### Assistant

這段話的核心不是在說「傳統程式沒用了」，而是在說：

**軟體的決策中心，正在從「人先寫死規則」轉成「系統根據資料與情境動態推斷」。**

---

## 1. deterministic 程式是什麼

deterministic 的意思是：

**在相同輸入、相同狀態下，輸出固定。**

例如：

- 稅額公式寫死
- 訂單流程固定：下單 → 付款 → 出貨
- 權限判斷固定：A 角色只能看 A 頁面
- 表單驗證固定：長度不夠就是錯

這種系統的特徵是：

- 規則由工程師明確定義
- 行為可預測
- 比較容易測試
- 一套流程可以複製給所有客戶

本質上就是：

**工程師先決定世界怎麼運作，使用者只能走既定路徑。**

---

## 2. 這段話說的 non-deterministic 是什麼

這裡講的 non-deterministic，不是在理論計算機科學裡那種嚴格定義，而是比較接近：

- **probabilistic**
- **model-based**
- **adaptive**
- **data-driven**

也就是：

**系統不是完全照寫死規則跑，而是會根據資料、上下文、歷史行為、環境訊號，動態調整輸出。**

例如：

- 推薦系統根據你點過什麼，改變你看到的內容
- 廣告系統根據你的轉換率，調整投放順序
- 搜尋排序根據你的地點、裝置、歷史偏好，改變結果
- 客服 bot 根據上下文生成不同回應
- 防詐/風控系統根據異常分數決定是否攔截
- IDE / coding assistant 根據你的 repo、檔案內容、先前操作，給不同建議

這時候系統不是只有「if/else」，而是有一層模型在做判斷。

---

## 3. 這句話真正想對比的是什麼

它在對比兩種軟體時代：

### 第一種：規則驅動時代
你設計一條固定流程，所有客戶都走同一條路。

例如：

- 每個人看到一樣的畫面
- 每個人點按鈕後走一樣流程
- 每個客戶套同一份 SOP
- 軟體像工廠生產線

### 第二種：模型驅動時代
你不再只交付「流程」，而是交付一個**會根據人與情境調整的決策系統**。

例如：

- 不同使用者看到不同首頁
- 不同客戶被分配不同操作順序
- 不同輸入會觸發不同提示與策略
- 同一個功能，對不同人展現不同形態

所以這段話的意思是：

**軟體的核心不再只是執行固定流程，而是持續推斷「現在對這個人最適合的是什麼」。**

---

## 4. 為什麼會發生這個轉變

因為很多真實世界問題，根本不適合完全寫死。

### 傳統寫死規則適合：
- 報表計算
- 會計邏輯
- 庫存扣減
- 核銷流程
- 權限控管

這些東西需要一致性與可追溯性。

### 但這些問題不適合全寫死：
- 使用者會想看什麼
- 哪個通知最可能被點
- 哪種文案最容易成交
- 哪筆交易最像詐騙
- 這段文字應該如何摘要
- 這個人現在真正想完成什麼任務

這些問題本身就有不確定性。

你沒辦法靠工程師預先列完所有規則。
所以系統開始依賴：

- 歷史資料
- 行為訊號
- 機器學習模型
- 即時上下文
- 概率推斷

---

## 5. 「根據你的使用環境跟使用經驗建立模型」是什麼意思

這句話可以拆成兩層。

### 第一層：顯性個人化
系統根據你可觀測到的資訊調整行為，例如：

- 地區
- 裝置類型
- 使用時間
- 點擊歷史
- 停留時間
- 購買記錄
- 常用功能
- 錯誤操作模式

這其實已經是在建一個「你是怎樣的使用者」的近似模型。

### 第二層：隱性行為建模
系統不一定明說，但它其實在學：

- 你偏好什麼介面
- 你容易在哪裡流失
- 你會不會付費
- 你需要多詳細的引導
- 你屬於哪一類使用群體

也就是：

**它不只是執行功能，而是在推測你的行為模式。**

---

## 6. 這跟以前的「設定檔」有什麼不同

以前也有客製化，但那叫：

- 參數化
- 設定化
- 規則分支

例如：

- VIP 客戶走 A 流程
- 一般客戶走 B 流程
- 台灣區顯示繁中，美國區顯示英文

這仍然是 deterministic。

因為規則還是工程師明確寫死的。

現在的差別在於：

**系統不只套用你預先定義的分支，而是自己從資料中學出權重與偏好。**

也就是：

- 不是你手動定義「什麼樣的人該看到什麼」
- 而是模型從資料中估計「這個人現在最可能需要什麼」

這是本質差異。

---

## 7. 這種轉變對工程意味著什麼

以前工程師主要在寫：

- 規則
- 流程
- 狀態機
- API
- 資料結構

現在越來越多工程工作變成在管理：

- prompt
- model behavior
- ranking
- retrieval
- feedback loop
- evaluation
- guardrails
- fallback logic

也就是從：

**「精確描述每一步」**

轉成

**「定義目標、上下文、邊界，讓系統自己找解法」**

所以工程重心從 coding only 變成：

- system design
- behavior shaping
- model evaluation
- observability
- risk control

---

## 8. 這不代表所有軟體都應該 non-deterministic

這點很重要。

不是所有東西都該交給模型。

### 必須 deterministic 的部分：
- 金流
- 帳務
- 身份驗證
- 權限檢查
- 法規遵循
- 關鍵資料更新
- 可稽核流程

因為這些地方需要：

- 穩定
- 可重現
- 可驗證
- 可追責

### 可以 non-deterministic 的部分：
- 推薦
- 排序
- 文案生成
- 搜尋理解
- 輔助決策
- 智能介面
- 互動式客服
- coding suggestion

所以現實中的好系統通常不是全 deterministic，也不是全 non-deterministic。

而是：

**用 deterministic 系統保證底層正確性，用 non-deterministic 模型提升上層適配性。**

---

## 9. 用一句話重述這段話

這段話真正的意思是：

**過去軟體主要是把工程師寫好的規則，等比例套到每個人身上；現在軟體越來越像一個會觀察你、推測你、並根據情境動態調整輸出的系統。**

---

## 10. 最精準的技術版翻譯

可以改寫成這樣：

> 傳統軟體以明確規則與固定流程為核心，在相同條件下產生可預測結果；新一代軟體則越來越多地嵌入資料驅動與機率式模型，根據使用者行為、上下文與環境訊號即時調整決策與介面，因此系統行為不再完全由工程師逐步寫死，而是部分由模型推斷產生。

---

## 11. 最後補一個常被混淆的點

很多人把這叫做「AI 化」。

但更準確地說，這是：

**從 rule-based software 轉向 model-mediated software。**

重點不是有沒有聊天介面，也不是有沒有大模型。
重點是：

**軟體的行為來源，從人寫死的規則，轉成資料訓練出的參數與即時推斷。**

這才是那段話真正要講的事。
